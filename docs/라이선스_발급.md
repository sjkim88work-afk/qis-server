# 라이선스 발급 절차 (발급자용 · 내부 문서)

QIS는 **영구 사용권 + 연 유지보수, PC 대수 제한** 방식입니다. 서버 없이 전자서명된 파일(`qis.lic`)로 동작합니다.

## 0. 처음 한 번 — 서명 키 만들기

```
python scripts/license_tool.py keygen
```
- 비밀키가 `~/.qis/qis-license.key`에 생깁니다. **백업해 두고 절대 공유·커밋하지 마세요.** 잃으면 기존 고객 라이선스를 다시 발급할 수 없습니다.
- 출력된 공개키를 `qis/license.py`의 `PUBLIC_KEY`에 넣고 커밋 → 그 뒤 빌드부터 이 키로 서명한 파일을 받아들입니다.
- 공개키가 자리표시(0000…)인 빌드는 어떤 라이선스도 받지 않아 30일 뒤 읽기 전용이 됩니다. **판매 전 반드시 바꿀 것.**

## 1. 고객이 보내는 것

고객이 QIS를 설치하고 관리 › **라이선스**(또는 데스크톱 메뉴 설정 › 라이선스)에서 **PC 코드**(예: `5RHA-6WC3-HHCB-GBTW`)를 복사해 보냅니다. PC 수만큼.

## 2. 발급

```
python scripts/license_tool.py issue --id L-2026-0001 --customer "한빛오토 품질팀" --seats 3 \
    --maintenance-until 2027-11-09 --machine 5RHA-6WC3-HHCB-GBTW --machine AAAA-BBBB-CCCC-DDDD \
    --out 한빛오토_L-2026-0001.lic
```
- `--seats` PC 대수, `--machine` 등록 PC(대수 이하, 나중에 추가 가능), `--maintenance-until` 유지보수 만료일(보통 발급일 + 1년 − 1일)
- 사내 서버 모드 동시 사용자 제한이 필요하면 `--users 5`. 평가용 기간제는 `--trial-until 2026-12-31`.
- 발급 기록은 `~/.qis/issued.jsonl`에 자동으로 남습니다.

## 3. 고객이 하는 것

받은 `.lic` 파일을 관리 › 라이선스 › **파일 선택** 으로 등록. 서명이 맞으면 즉시 정식이 되고 화면 새로 고침 후 배지가 사라집니다.

## 4. 운영 중

| 상황 | 명령 |
|---|---|
| PC 추가 (대수 안에서) | `license_tool.py add-machine 파일.lic 새PC코드` → 새 파일 전달 |
| PC 교체 | 기존 코드를 빼고 새 코드를 넣어 `issue` 다시 (같은 `--id`) |
| 대수 늘리기 | `--seats` 늘려 `issue` 다시 |
| 유지보수 갱신 | `license_tool.py renew 파일.lic --maintenance-until 2028-11-09` |
| 내용 확인 | `license_tool.py show 파일.lic` |

## 동작 규칙 (고객 안내용)

- 라이선스 없음 / 이 PC 미등록 → **평가판 30일**(모든 기능). 지나면 **읽기 전용**(보기·검색·출력·내보내기 가능, 저장 불가). 데이터는 지워지지 않고, 라이선스를 등록하면 바로 복구됩니다.
- 유지보수 만료일 **이전에 빌드된 버전은 영구 사용**. 그 뒤 버전을 설치하면 읽기 전용 → 유지보수 갱신 또는 이전 버전으로 돌아가면 됩니다. 업데이트 안내도 유지보수 기간 안의 버전만 보여 줍니다.
- 읽기 전용에서도 백업·내보내기·SQLite는 됩니다 (데이터 인질 없음).
- PC 코드는 윈도우 MachineGuid / 맥 플랫폼 UUID 에서 만들어집니다. OS 재설치 시 바뀔 수 있으니 그때는 PC 교체로 처리합니다.
